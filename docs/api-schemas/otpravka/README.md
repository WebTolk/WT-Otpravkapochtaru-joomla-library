# Наблюдаемые схемы ответов Otpravka REST API

Этот каталог содержит приложение к документации, построенное по реальным ответам REST API Почты России, полученным 11 июля 2026 года через пакет `WT Otpravkapochtaru` 3.0.0 на Joomla 5.

Тестовый маршрут: `410000 Саратов` -> `685000 Магадан`.

## Состав

- [`index.json`](index.json) - машиночитаемый индекс методов, маршрутов API, статусов и файлов контрактов.
- [`examples/`](examples/) - обезличенные примеры реальных JSON-ответов.
- [`schemas/`](schemas/) - JSON Schema Draft 2020-12, выведенные из наблюдаемых ответов.

Схемы описывают фактически наблюдавшуюся структуру одного прогона. Это не полная спецификация upstream API: необязательные поля, альтернативные типы и другие варианты ошибок могут отсутствовать.

## Результат прогона

Выполнено 29 REST-запросов при локальном пределе сценария 40. Метод получения остатка API не вызывался, трекинг не вызывался.

Успешно завершены 25 операций:

- нормализация адресов отправителя и получателя, ФИО и телефона;
- получение настроек аккаунта и точек сдачи;
- одиночная и пакетная проверка благонадёжности получателя;
- расчёт тарифа и срока доставки;
- поиск отделений по индексам, адресу и координатам;
- получение услуг отделения и индексов населённого пункта;
- создание заказа;
- изменение заказа;
- поиск заказа по API ID, `order-num` и РПО;
- создание партии, получение списка партий и заказов партии;
- возврат заказа из партии в состояние `NEW`;
- удаление заказа.

Жизненный цикл тестового заказа полностью очищен: `createOrders -> editOrder -> findOrderById -> findOrderByShopId -> createBatch -> returnOrdersToNew -> deleteOrders`.

## Наблюдаемые ошибки

- `generateDocumentPackage`: HTTP 400 для партии в статусе `CREATED`.
- `generateDocumentF103`: HTTP 400 для партии в статусе `CREATED`; у партии `electronic-f103=false`.
- `createReturnShipment`: ответ API с кодом `DIRECT_SHIPMENT_NOT_FOUND`.
- `createReturnShipments`: ответ API с кодом `FREE_ER_ADDRESS_NOT_ENABLED`.

Для двух document-методов библиотека выбросила исключение на HTTP 400, поэтому JSON-тело ответа не попало в вызывающий код. В `index.json` сохранена только метаинформация исключения; пример и схема ответа намеренно не выдумывались.

Изменение и удаление отдельного возврата не запускались: создание отдельного возврата отклонено настройками аккаунта, поэтому безопасного идентификатора созданной сущности не возникло.

## Обезличивание

Сырые захваты хранятся только в игнорируемой рабочей области `.webtolk/tmp/rest-api-capture-20260711/` и не предназначены для публикации. В репозиторий добавлены только производные файлы из этого каталога.

В примерах заменены:

- ФИО, телефоны и email;
- реквизиты и идентификаторы аккаунта;
- адреса владельца аккаунта и адресные данные заказа;
- API ID заказа, `order-num`, РПО, штрихкоды и имена партий;
- локальные пути файлов.

Типы обезличенных значений сохранены там, где это требуется для соответствия выведенной JSON Schema: числовые идентификаторы заменены на `0`, строковые значения - на маркеры `<redacted-...>`.

## Ограничения использования

Не используйте наблюдаемую схему как единственный источник для строгой валидации всех будущих ответов. Для production-кода учитывайте документированный контракт API, nullable-поля, новые поля и несколько вариантов ошибок.
